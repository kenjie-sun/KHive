# 配置与使用

## 基本配置

从 [config.example.yaml](../config/config.example.yaml) 创建本地 `config/config.yaml`。默认监听环回地址、通知关闭且没有已管理设备。首次启动前替换 `web.password`，并将文件权限设为仅运行用户可读写。

`server.port` 接受完整监听地址，例如 `127.0.0.1:8788`。仅使用端口数字会监听所有接口；需要从外部访问时，明确选择监听地址并配置访问控制。

配置文件可能由 Web 设置保存流程更新。不要把实际配置、通知密钥或登录凭据提交到仓库；示例文件只保留空凭据与占位内容。

## 设备发现与后端

推荐通过设备页面发现硬件、核对目标后添加。设备以 IMEI 匹配，串口、网卡和控制接口路径在运行期解析，不要照搬其他主机的 `/dev` 路径。一个模组应只有一个负责管理的程序，避免命令与网络配置相互干扰。

| 选项 | 说明 |
| --- | --- |
| `id`／`name` | 设备的本地标识和显示名称 |
| `modem_imei` | 实际模组身份，只保存在本地配置 |
| `device_backend` | `at`、`qmi`、`mbim` 或 `auto` |
| `esim_transport` | eSIM 使用的 `at`、`qmi` 或 `mbim` 通路 |
| `mbim_transport` | `auto`、`proxy` 或 `direct` |
| `qmi_use_proxy` | 是否通过 qmi-proxy 使用控制接口 |
| `esim_at_csim` | AT eSIM APDU 是否使用 CSIM；默认关闭 |

网络、VoWiFi、飞行模式、APN 和 IP 类型属于**按卡保存的策略**，在 Web 的卡策略中设置。切换或重新上线时，系统以确认后的卡身份应用相应策略。

## AT／ECM 数据网络

此路径要求模组已使用兼容的 ECM 模式，Linux 网卡驱动为 `cdc_ether`，系统具有 BusyBox `udhcpc`，且网卡没有被另一个网络管理器配置。KHive 不会为了开启该路径自动切换模组 USB 模式。

KHive 使用接口地址与独立路由表管理 IPv4 数据，断开、切卡或退出时清理自己创建的对象。ECM 暂不支持 IPv6 或运营商公网 IP 轮换，DHCP 续租不等于运营商重新分配公网 IP。

## eSIM 与二维码

在“下载新 Profile”中选择目标 eUICC，并输入激活资料或上传二维码照片。照片在浏览器本地识别，确认表单后才提交下载；图片不会上传到 KHive 或第三方解码服务。支持浏览器可解码的 JPG、PNG、WebP 等格式，文件最大 10 MB；HEIC 可先转为 JPG。

下载不会自动启用新卡。操作结束后核对新增 Profile、状态及通知结果，再决定是否切换。当前启用的 Profile 不能直接删除，停用卡的删除也不可撤销。不同运营商对激活码复用、EID 绑定和确认码有不同约束，不能假定删除后可以重新下载。

若请求中断、响应丢失或提示结果未知，先刷新卡列表并检查通知，避免直接重复发送安装或删除请求。安装已完成而通知未成功时，应处理通知，无需再次下载同一 Profile。

部分 AT 固件的 CGLA 通路会过早报错。仅在已确认该模组支持逻辑通道 CSIM 时，可在对应设备配置下增加：

```yaml
esim_at_csim: true
```

该选项需重启程序生效，只影响该设备的 AT eSIM APDU；仍使用 CCHO/CCHC 管理通道，不会在写入失败后切换另一通路重发。恢复默认设为 `false`。不要按模组品牌统一启用。

## 短信、VoWiFi 与通知

VoWiFi 依赖实际 SIM 认证、运营商开通情况和网络可达性。先确认隧道、IMS 注册和短信通路状态，再判断业务是否可用。USSD 和网络代理的具体能力同样取决于后端及运营商。

状态中的 `register_template=default-ims-register` 表示默认 IMS 注册协议模板，不代表 SIM 运营商；`preset_id` 是另一个字段，表示选中的运营商参数预设。实际卡信息应结合当前 SIM 身份与启用的 eSIM Profile 判断。

发送状态区分信令接受、提交确认、明确失败与未确认。`unconfirmed` 表示未得到足够回执，不等于短信未发送；不要因此自动重发验证码或计费短信。

短信会话中的“发送与终端回执”显示最近 20 条发送记录，每 10 秒刷新。RP-ACK／AT 提交成功与 SMS-STATUS-REPORT 分开保存；只有 TP-ST `00` 显示“已送达终端”。长短信逐片展示，未报告的分片保留待确认状态，迟到的临时失败不会覆盖最终结果。状态含义依据 [3GPP TS 23.040 §9.2.3.15](https://www.etsi.org/deliver/etsi_ts/123000_123099/123040/18.00.00_60/ts_123040v180000p.pdf)。

VoWiFi 在发送前持久化每片 TP-MR 并请求终端回执；同一 SIM 的引用号在 24 小时内不重复分配，全部 256 个占用时拒绝继续提交。AT 后端使用模组返回的 `+CMGS` 引用号，优先接收直接上报的 `+CDS` 报告；若固件不支持则回退到存储型 `+CDSI`，持久化成功后才删除模组记录。两种报告模式均不支持时，继续普通短信发送并记录不追踪回执。直接报告按接收时的 SIM 身份入库，避免异步处理期间切卡造成错配；`CSMS=1` 时先持久化再发送 `CNMA`，`CSMS=0` 时由模组负责网络确认。QMI／MBIM 发送目前不追踪终端回执；支持报告也不保证运营商一定返回。

AT 初始化、VoWiFi 退出或重连、切卡后 SIM 重载完成时共用回执配置：依次尝试 `AT+CNMI=2,1,0,1,0`（直接报告）、`AT+CNMI=2,1,0,2,0`（存储报告）、`AT+CNMI=2,1,0,0,0`（普通短信）。SIM 重载可能重置先前的配置，因此须在 SIM 就绪后重新应用；三种配置均失败时，切卡恢复会报告降级。收到终端回执需要发送方 SIM 在线；切换到接收方 Profile 后，发送方的报告可能需要再次启用该 Profile 才能接收。

上述 AT 处理遵循标准短信报告格式，不按运营商或 eSIM.gg 特判；其他运营商是否返回报告取决于其网络、套餐及漫游路径。eSIM.gg 的成功测试不代表所有运营商均已实测。

回执只按 SIM、完整收件号码、TP-MR 和时间范围匹配；引用号复用产生多个候选时保留为歧义，不猜测匹配。报告先于 AT 引用号到达时先入库，关联建立后重放。重启后仍可查询历史发送状态。

通知凭据通过本地配置或 Web 设置保存。完整收信与各已启用渠道的通知队列在同一数据库事务提交；重复分片不重复入队。各渠道独立消费，失败从 5 秒开始指数退避，最多尝试 10 轮，之后可在设置页手动重试；每轮仍遵循渠道自身的请求重试设置，实际 HTTP 次数可能更多。重启会恢复待发送和到期租约，已发送记录不能手动重排。

关闭渠道暂停已有队列，重新启用时使用**当前渠道配置**，包括当前接收人／URL；新启用的渠道不会补发启用前的历史短信。外部服务已接受、但本地还没记录结果就退出时，可能重复通知；Webhook 的 `notification_id` 保持不变，可用于接收端去重。渠道内有多个目标时，部分目标成功、部分失败也可能在重试时重复通知成功目标。Telegram 等渠道返回成功表示服务端接受，不保证终端弹窗。提供日志时移除号码、短信正文、密钥和完整卡片身份。

## 前置代理探测

保存、修改和主动探测 SOCKS5 前置代理时，依次检查 TCP、认证、UDP ASSOCIATE，再经代理向 `1.1.1.1:53` 发出 `example.com` 的 DNS 查询并验证返回。仅成功创建 UDP 会话不能通过探测；结果分别暴露 `udp_associate_ok` 和 `udp_exchange_ok`。

DNS 返回错误码仍能证明双向 UDP 可达，错误码保存在 `dns_rcode`；超时则不能证明 UDP 可用。此检查验证该 DNS 目标的 UDP 通路，不能代替 ePDG 的 UDP 500／4500、IKE 或 IMS 实际验证。仅允许特定 UDP 目标的代理可能无法通过此探测。

## 同一 PLMN 下的运营商规则

程序启动时从工作目录的 `data/carrier_overrides.json` 读取 JSON 数组；修改后重启生效。现有不带 `match` 的 PLMN 条目保持原有行为。带 `match` 的规则按 SIM 信息细分，不改变 SIM 的归属 MCC／MNC。

```json
[
  {"id":"host-example","mcc":"234","mnc":"10","epdg_addr":"host.example.invalid"},
  {
    "id":"mvno-example","mcc":"234","mnc":"10","priority":10,
    "match":{"imsi_prefix":["23410099"],"spn":["Example Mobile"],"gid1":["01","02"]},
    "epdg_addr":"mvno.example.invalid",
    "aka_app_preference":"usim"
  }
]
```

以上仅为格式示例，不能作为实际运营商配置。`match` 支持 `imsi_prefix`、`iccid_prefix`、`spn`、`gid1` 和 `gid2`；不同字段同时满足，同一字段数组内任一值满足。身份前缀只接受数字；SPN／GID 精确匹配且不区分大小写，GID 使用偶数位十六进制。缺失的 SIM 信息不能满足对应条件。

匹配优先选择较高 `priority`，同优先级选择约束字段更多、身份前缀更长的规则；仍并列时停止启动并报规则歧义。无 SIM 规则匹配时依次回退外部 PLMN、内置预设和 3GPP 默认值。选中条目作为完整预设使用，不与基础 PLMN 条目逐字段合并；需要保留的基础字段应在具体规则中明确填写。选中的预设统一影响 ePDG、AKA、REGISTER、P-CSCF、小区标识和 E911 可用性。启动日志记录 `preset_id` 与 `match_source`，不会为匹配诊断新增完整 SIM 身份日志。

## API

管理 API 位于 `/api/`，使用系统现有登录认证。接口定义见 [OpenAPI](../internal/api/openapi.vohive.yaml)，卡策略详见 [卡策略 API](CARD_POLICY_API.md)。

eSIM 下载使用 `POST /api/devices/{device_id}/esim/actions/download` 和 JSON 请求体，不使用 GET query 传递激活资料；旧脚本需要适配此调用方式。切卡进度和设备会话可用于拒绝失效操作，客户端不能把连接断开直接解释为卡内写入失败。
